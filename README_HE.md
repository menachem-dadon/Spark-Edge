# SparkMoE

**מודלים מקומיים ענקיים על חומרה צנועה.**

SparkMoE הוא fork עצמאי של `llama.cpp` שמיועד להרצת מודלי שפה גדולים, ובמיוחד מודלי MoE, גם כאשר אין מספיק RAM כדי להחזיק את כל משקלי המומחים בזיכרון בו-זמנית.

במצב `explicit`, משקלי המומחים המנותבים נשארים בקובץ GGUF. רק המומחים שה-router בחר נטענים למטמוני RAM מוגבלים לפי שכבה. יתר משקלי המודל, שרת ההסקה, ממשק הצ'אט, GGML ותמיכת הארכיטקטורות מגיעים מ-llama.cpp.

זוהי גרסת **v0.2.0-alpha**. Qwen3.6 35B-A3B ו-Gemma 4 26B-A4B עברו בדיקות קצרות של טעינה, paging והפקת טוקנים ב-Windows, ושכבת המטמון ומיפוי הקבצים מכוסה גם בבדיקות דטרמיניסטיות. מודלי MoE נוספים בעלי פריסת expert tensors תואמת מתקבלים באמצעות בדיקת layout כללית. עדיין אין הבטחה שכל quantization או מודל יתאים למחשב מסוים.

## התקנה קבועה ב-Windows

1. הורידו מדף ה-Release את `sparkmoe-0.2.0-alpha-windows-x64-avx2-setup.exe`.
2. הפעילו את המתקין.
3. המתקין מתקין לתיקיית המשתמש, מוסיף אפשרות הסרה ב-Windows ויוצר קיצור דרך בתפריט Start. אפשר לבחור גם קיצור דרך לשולחן העבודה והוספה ל-PATH.
4. הפעילו `SparkMoE` מתפריט Start.

## הפעלה ללא התקנה

1. חלצו את חבילת ה-ZIP לתיקייה עם הרשאת כתיבה.
2. הפעילו `SparkMoE.exe`.
3. בחרו תיקיית מודלים, ואז בחרו מודל `.gguf` מהרשימה.
4. השאירו את שיטת הטעינה על **Automatic**. התוכנה תשתמש בטעינת מומחים במודל MoE תואם, ותעבור אוטומטית ל-mmap רגיל במודל dense או במודל שאינו תואם.
5. הפעילו את המודל ופתחו את ממשק הצ'אט.
6. בתוך הצ'אט הגדירו אורך הקשר ו-MTP תחת **Settings -> Context & MTP**.

## מה ניתן לשלוט מהממשק?

- בדשבורד: תיקיית מודלים, בחירת מודל מהרשימה ושיטת הטעינה.
- בדשבורד: גודל מטמון המומחים, מספר slots ומספר תהליכי קריאה מה-SSD.
- בדשבורד, תחת הגדרות מתקדמות: מספר תהליכי חישוב ושליטה במצב CPU repack לצורכי ביצועים ותאימות.
- בדשבורד: סטטוס השרת, לוגים, שימוש RAM אמיתי ומדדי paging חיים.
- בצ'אט: מספר ישיר של טוקנים בהקשר ובחירה אם למחוק הודעות ישנות או לעצור כשההקשר מלא.
- בצ'אט: הפעלה והגדרה פשוטה של MTP במודלים תואמים.
- בצ'אט, תחת הגדרות מתקדמות סגורות: batch, microbatch, סוגי KV cache ומטמון prompts.
- הורדת קובץ אבחון ואיפוס סטטיסטיקות.

שינוי אורך ההקשר או MTP מתוך הצ'אט מבצע restart מבוקר של השרת. השיחות נשארות שמורות בדפדפן.

SparkMoE מתאימה גם למודלים רגילים שאינם MoE ומריצה אותם במסלול הרגיל של llama.cpp. מצב `auto` הוא ברירת המחדל: הוא מנסה טעינת מומחים כאשר הוגדר מטמון והמודל תואם, ובמודל dense או לא תואם הוא חוזר אוטומטית לטעינת mmap רגילה.

## מצבי טעינה

- `off`: טעינה רגילה של llama.cpp ללא מנגנון SparkMoE.
- `os`: שימוש רגיל ב-`mmap` ובמנהל הזיכרון של מערכת ההפעלה.
- `explicit`: טעינת מומחים מדויקת מהכונן למטמוני slots מוגבלים.
- `auto`: ברירת המחדל המומלצת. בוחר explicit כאשר הוגדר תקציב cache או slots והמודל תואם; אחרת חוזר ל-OS paging רגיל.

SSD מומלץ מאוד. מנגנון paging אינו מבטל את הזיכרון שנדרש למשקלים קבועים, ל-KV cache, להקשר ולתקורות הריצה.

## בנייה מקוד המקור

```powershell
git clone https://github.com/menachem-dadon/SparkMoE.git
cd SparkMoE
pwsh scripts/build-windows.ps1 -Variant avx2 -RunTests
.\build-windows-avx2\bin\SparkMoE.exe
```

ליצירת ZIP ומתקין:

```powershell
.\scripts\package-windows.ps1 -BuildDir .\build-windows-avx2 -Variant avx2
.\scripts\build-installer.ps1
```

## איפה נמצא הקוד של SparkMoE?

- `src/moe-paging/`: האלגוריתם, המטמון, קריאת הקבצים והסטטיסטיקות.
- `tools/sparkmoe/`: מנהל התוכנה וה-dashboard.
- `tools/sparkmoe-iobench/`: כלי בדיקת הכונן.
- `SettingsChatServerTab.svelte`: מסך הגדרות השרת בתוך ממשק הצ'אט.
- `scripts/` ו-`packaging/`: בנייה, חבילות ומתקין.
- `assets/branding/`: אייקון התוכנה וה-dashboard.

למיפוי מלא וברור קראו את [מפת הפרויקט](docs/PROJECT_MAP.md).

## הקשר ל-llama.cpp

SparkMoE כולל snapshot מלא של llama.cpp ולא תלות חיצונית. לכן קיימות בו התכונות שהיו בגרסת upstream הרשומה ב-`UPSTREAM_BASE.txt`, בתוספת יכולות SparkMoE. תכונות חדשות שנוספו מאוחר יותר ל-llama.cpp אינן מגיעות אוטומטית ודורשות merge מבוקר ובדיקות חוזרות.

## פרטיות

אין telemetry, analytics, העלאת קריסות או הורדת מודלים אוטומטית. מנהל SparkMoE מאזין רק ב-`127.0.0.1`. חשיפת `llama-server` לרשת דורשת API key והגדרות אבטחה מתאימות.
